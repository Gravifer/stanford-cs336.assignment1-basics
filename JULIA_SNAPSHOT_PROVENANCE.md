# Julia snapshot provenance map

This inventory describes the 14 NumPy snapshots currently readable by the Julia test project. It is a migration aid, not a claim that the snapshots are self-contained parity fixtures.

## Shared fixture generation

The model tests use these Python-side dimensions and deterministic generators:

| Symbol | Value or producer |
| --- | --- |
| batch | 4 |
| query/sequence length | 12 |
| key/context length | 16 |
| model width | 64 |
| heads | 4 |
| head width | 16 |
| feed-forward width | 128 |
| layers | 3 |
| vocabulary | 10,000 |
| input embeddings | PyTorch seed 4, shape `(batch, query, model)` |
| token IDs | PyTorch seed 6, integer values in `[0, 10_000)`, shape `(batch, query)` |
| Q/K/V | PyTorch seeds 1/2/3; shapes `(batch, query, model)`, `(batch, key, model)`, `(batch, key, model)` |
| attention mask | PyTorch seed 5, boolean shape `(batch, query, key)` |
| positions | zero through 11 |
| RoPE base | 10,000 |
| model parameters | `tests/fixtures/ts_tests/model.pt` |

The random tensors are regenerated by PyTorch rather than stored. A Julia RNG with the same integer seed is not expected to reproduce them. The model checkpoint is a PyTorch serialization rather than a neutral parameter bundle.

“Snapshot default” means the repository's `NumpySnapshot` defaults, currently relative `1e-4` and absolute `1e-2`. The unusually large default absolute tolerance is another reason to copy tolerances deliberately into neutral bundle metadata rather than treating snapshot presence as a strict parity claim. The Julia reader currently checks container compatibility, dtype, and shape only; it does not apply these numerical tolerances yet.

## Self-contained replacements now available

The versioned `tests/fixtures/julia_parity/v1/` directory now contains
self-contained replacements for RoPE, four-dimensional scaled dot-product
attention, causal MHA, causal MHA with RoPE, the transformer block, and a tiny
two-layer transformer LM. They store every input, semantic projection
parameter, expected output, dense input/parameter gradient, logical axis name,
tolerance, and producer/source version. Julia tests transpose each Python
boundary array once into feature-first order and then execute only native
Julia kernels. The tiny LM bundle avoids coupling parity tests to the large
PyTorch checkpoint while still exercising independent parameters in two
blocks.

## What remains missing from legacy snapshots

Every NPZ file contains one `Float32` output under the key `array`. None contains its input arrays, masks/IDs, parameter arrays, expected gradients, logical axis names, tolerance metadata, or producer versions. The AdamW output additionally depends on a long PyTorch RNG sequence, and the orphaned feed-forward snapshot has no live producer.

Therefore the legacy files remain useful expected outputs but are not neutral
cross-language fixtures. Operations without a corresponding versioned bundle
must still follow `JULIA_FIXTURE_CONTRACT.md`; do not regenerate inputs with
Julia's RNG or make the package parse `model.pt` as its long-term interchange
format.
